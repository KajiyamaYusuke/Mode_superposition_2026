# 第1・4・5モードの最小終了試験：Codex実装仕様

## 1. 目的と終了範囲

現在の非振動・開放平衡について、流体が各モードを励振しているか、構造減衰を補えているかを判断し、次の係数探索へ進む。対象は `live` と `freeze_fluid` の2条件、左右の第1・4・5モードだけ。

- `freeze_contact` / `freeze_all` の追加解析・再計算は不要。
- 接触係数探索、全100モード解析、流れ場の追加診断、新しい大規模診断基盤は作らない。
- 既存スクリプト・出力を調べ、使える部分を再利用する。必要な場合だけ小さく拡張する。
- 実際のリポジトリの `AGENTS.md` に従う。診断追加で物理式・積分器・既定出力を変更しない。

## 2. 現在分かっていることと最初の確認

観測変位では `live ≈ freeze_contact`、`freeze_fluid ≈ freeze_all`。接触力の動的影響は小さいという証拠がある。接触の物理的妥当性を保証する結果ではないが、この終了試験では接触原因の追究を止める。

今回の変位・流体CSVは0～0.4秒、条件差は約0.20秒から発生。以前の `modal_force_selected.csv` は0～0.7秒の別live計算であり、その平衡窓0.25～0.30秒・擾乱時刻0.35秒を今回へ流用してはいけない。

既知の `modal_force_selected.csv` には `q,qdot,frequency_hz,fluid_force,applied_force,structural_damping_force,load_time_s,state_time_s` がある。今回の2条件について同じ情報を取得できれば後処理は可能。ただし、間引きデータの仕事は概算である。

Codexは最初に次を確認して短く報告する。

1. `summarize_modal_force_split.py`、`run_ap_contact_diagnostics.py`、`perturbation_energy*.csv` の生成・集計機能を確認。既にモード別の内部dt積分があるなら再利用する。
2. 今回の2条件の元データが残っているか、選択モードを内部dtで取り出せるか確認。
3. manifest/paramsから凍結時刻、実際の凍結基準荷重、擾乱の有無・時刻、dt、減衰係数、モード周波数・正規化を確認。
4. 既存出力だけで厳密な集計ができるか、概算までか、2条件の再計算が必要かを区別する。

`displace.dat` は観測点の合成変位なので、ここからモードのq・qdot・一般化力を逆算しない。流体CSVの圧力も、そのまま一般化力として使用しない。

## 3. 最小実装

推奨：`tools/analyze_modal_exit_test.py` を追加、または既存集計スクリプトへ終了試験モードを追加。

入力はlive/freeze_fluidのrun directory、モード指定（既定 `1,4,5`）、解析窓、必要なら平衡基準窓。時刻は設定ファイルから取得し、CLIで上書き可能にする。今回の凍結時刻約0.20秒は確認して使い、既定値として埋め込まない。

### データ取得の優先順

1. 既存の内部dtモード別仕事・減衰積分を利用。
2. 残存する内部dtの `modal_force_split.csv` をchunksで読む。左右×3モードだけ抽出し、メモリに全ファイルを載せない。
3. 間引きCSVしかないなら概算集計を先に行う。結論が積分間隔や窓で変わる場合だけ再計算する。
4. 再計算が必要なら、左右×3モードの仕事を内部dtで累積する小さな診断を追加し、2条件だけ実行する。全モード巨大CSVを再生成しない。

採用したdt、間引き間隔、run identity、仕事の積分方式を出力に記録する。

### 必須の状態・荷重

`case,side,mode_index_1based,frequency_hz,c_i,load_time_s,state_time_s,q,qdot,Q_fluid_applied,Q_total_applied`

- 質量正規化された式 `qddot + c_i*qdot + omega_i^2*q = Q_i` を前提とし、実装と照合する。
- `omega_i=2*pi*frequency_hz`。`c_i` は実際に積分器が使う値を取得する。一定ζなら `c_i=2*zeta_i*omega_i`。ζ=0.06を無条件にハードコードしない。
- 計算された流体力と実際に適用された流体力を区別する。freeze_fluidでは適用力は凍結値。流体CSVが変動していても構造への荷重が変動しているとは限らない。
- 既存の `fluid_force` 列がcomputed/appliedのどちらかをコードで確認する。`applied_force` は合力であり、そのまま流体成分とみなさない。
- generalized unitsのまま出力可能。SI整合が確認されるまでJ/W表記をしない。

## 4. 仕事・減衰の定義

各モードについて、解析窓 `[a,b]` で次を計算する。

```
W_fluid_raw = integral(Q_fluid_applied * qdot dt)
D = integral(c_i * qdot^2 dt)  >= 0
W_static = Q_fluid_ref * (q(b)-q(a))
W_fluid_dynamic = W_fluid_raw - W_static
```

生の流体仕事には、一定圧力で平衡位置へ移動する仕事も含まれる。そのため **rawの符号だけで励振・減衰を分類しない**。rawとdynamicの両方を残す。

`Q_fluid_ref` は信頼できる平衡流体荷重を使う。実際の凍結基準値も別に記録し、平衡値と自動的に同一視しない。freeze_fluidは、実際の凍結値を差し引けば変動流体仕事がゼロになることを実装確認に使えるが、これは力が一定であることによる恒等的な確認。

平衡基準が不確かなら、今回の既存データから同じq・同じ移動方向の周期境界を選び、端点変位差による定常荷重仕事を小さくする。境界のずれを記録する。**単なる時間平均値を平衡値と断定しない。** 基準荷重を合理的な範囲で変えて結論が変わるなら保留とする。

### 時刻と積分

- 現行出力では荷重がt、状態がt+dtの場合がある。行の `Q(t)*qdot(t+dt)` をそのまま厳密な仕事として足さない。
- 既存内部dtの仕事計算があるなら、その荷重時刻・状態時刻・積分器との整合を確認して再利用する。
- 新規実装では、現在の積分器が実際に用いる荷重・状態の評価時刻に合わせて求積する。1ステップ一定荷重なら `Q_n*(q_{n+1}-q_n)` が仕事の自然な定義。減衰積分はステップ内速度の適切な求積を使う。
- 間引き出力を積分する場合は概算と明記し、隣接サンプルの実時間差を用いる。内部dtを掛けて過小評価しない。
- 擾乱注入ステップは窓から除外するか、注入仕事を別記する。圧力ランプ中は終了判定に使わない。

## 5. モード別の比較

各モードに対し、live/freeze_fluidの `q(t),qdot(t)` を重ねて表示。平衡変位の差と振動振幅を区別する。

既存の成長率推定機能を再利用する。なければ、信頼できる基準qを用いた振幅 `sqrt((q-q_ref)^2+(qdot/omega_i)^2)` または周期ごとの振幅に対するlog fitで簡単に評価する。小振幅の数値ノイズ域は除外し、fit窓・残差を記録する。基準qが不確かな場合は周期振幅を優先する。

観測点の85～90 Hzと45～47 Hzの差だけから、モード別減衰の符号を決めない。比較対象は同じ側・同じモードとする。

## 6. 分類と終了判定

まずliveの各モードを次で分類する。判定量は振動に対する `W_fluid_dynamic`、比較量は同じ窓のD。

| 判定 | 条件（数値誤差を超える差） | 次に進む方向 |
|---|---|---|
| EXCITING_INSUFFICIENT | 0 < W_dynamic < D | 流体は励振するが減衰を補えていない。ζ/Ps探索へ進む根拠 |
| FLUID_DAMPING | W_dynamic < 0 | 圧力分布・剥離条件・一般化力と速度の位相を優先 |
| INPUT_AT_LEAST_DAMPING | W_dynamic >= D | 流体入力は構造減衰以上。接触仕事・エネルギー変化・積分誤差など既存収支と照合 |
| NEAR_ZERO_OR_INCONCLUSIVE | 零付近、Dが数値床以下、窓/基準で分類が変わる | このモードでは断定しない |

モードごとに符号が異なれば全体の結論を `MIXED_MODAL_EFFECT` とする。これはモードごとに異なる流体作用の証拠であり、モード間の直接的なエネルギー移送を証明したとは書かない。

- 主窓と隣接する確認窓の2窓だけを使う。今回の既存データなら例として0.22～0.30秒、0.30～0.38秒を試せるが、凍結直後・擾乱・周期端点・信号振幅を確認して決める。
- 数値誤差の目安は内部dt積分と間引き積分、または利用可能な2種類の求積結果の差から記録する。固定の絶対閾値だけで符号を判定しない。
- 累積仕事だけで判断せず、周期単位または確認窓でも傾向が維持されるかを見る。
- 既存の合力・接触合力があれば、エネルギー収支を低コストで照合する。接触領域別解析は追加しない。収支不整合が分類を左右するなら保留。

**終了条件：** 左右第1・4・5について、流体仕事の符号・Dとの比・live/freeze_fluidの同一モード応答が一覧になり、判定の安定性が分かれば終了する。左右一致なら本文は片側を代表にしてよいが、左右一致の数値確認は残す。

全モードの確定を追わない。不確定モードが残っても、確定した主要モードの根拠と不確定理由を記録して次の探索へ進む。決定的な不足がある場合も、追加確認は不足を埋める最小の2条件計算に限定する。

## 8. 必要な検証のみ

- 同じrun由来の2条件で、凍結/擾乱前の対象モードの状態が一致する。
- freeze_fluidの実際の適用流体力が一定で、凍結値を基準にしたW_dynamicが数値誤差内でゼロ。
- Dが非負。raw = dynamic + staticの関係が求積精度内で成立。
- 仕事の時刻対応、単位、周波数Hz→rad/s、実際の減衰係数が正しい。
- 既存集計と一致する部分は照合する。C++変更がある場合のみReleaseビルドと、診断追加前後の同条件数値出力比較を行う。
