## 3. 調査A：ばね仕事の符号差の「いつ・どこで・どのモードで」を分解

### A1. 既存rawからステップ仕事系列を再構成

**新runの同一ディレクトリ内**の`contact_component_native.bin`と`modal_native.bin`を、そのrunのmetadataに従って読み込む（**7-field旧形式のまま、別2-field追加を想定。必ずmetadataの実値を正とする**）。各区間・side・mode：

\[
\Delta W^{spring}_{s,m,n}=Q^{spring}_{s,m,n}\Delta q_{s,m,n},\quad
\Delta W^{damp}_{s,m,n}=Q^{damp}_{s,m,n}\Delta q_{s,m,n}.
\]
\[
\Delta W^{contact}_{s,m,n}
 = (Q^{spring}_{s,m,n}+Q^{damp}_{s,m,n})\Delta q_{s,m,n}.
\]

モード`q`・`Δq`・`Q`は**同一新run**から取り、過去runの`Q`と新run`Δq`を混ぜない。`step n`、`t_n=n\,dt`、`[t_n,t_{n+1})`と最終無効区間を一致させる。`nstep−1`区間、各側20モードの要件を確かめる。

- side×stepで`sum_mΔW_spring/damp/total`、その累積和を計算。
- 仕事の正値と負値の絶対和、正味値、正寄与区間数/負寄与区間数、非ゼロ荷重時の占有率、上位1%/5%のイベントが負仕事総量に占める割合。
- 主窓`[0.30,0.50)`、副窓`[0.10,0.20)`、`[0.20,0.30)`、`[0.30,0.40)`、`[0.40,0.50)`。任意の短いイベント窓も別途提示してよいが、主窓と混同しない。
- 初期区間や終端の同じ区間を二重計上しない。**負荷がないときのゼロ仕事と未保存値は区別**する。

各窓で`W_spring+W_damp=W_total`、step別でも成立すること、報告済み主窓のL/R数値と差が再現できることを検算。

### A2. ばね仕事の符号は必ず`F·Δu`の関係で見る

現行`ForceCalculator::applyContactLoads`では、各接触ペアについて法線、貫入、`f_spring`/`f_damp`（**圧力Pa**）、接触面積`area`を得て、
- L: `F_spring,L=−p_spring·area·n`
- R: `F_spring,R=+p_spring·area·n`
を対応する表面節点へ分配する。各側の**実際に採用された荷重**と最終更新変位の`Δu`を用いて節点仕事が求まる。**Pair-local法線速度の瞬間powerは別の補助量**であり、正負をそのまま今回の`Q Δq`へ移し替えない。

保存済み`contact_component_regions.csv` / `contact_component_region_summary.csv`に**AP領域別の節点仕事**があれば、それらで`W_spring(AP端/中央)`、`W_damp`、正負の時刻分布を描く。**地域別の力の合計×代表点変位を地域別仕事とみなすことは禁止**。全節点時系列がなければ、AP地域仕事は既存の集計値までとし、局所の節点単位の機構解釈は保留する。

可能な範囲で**同時刻**の以下を対応させる：
- spring節点`F_open`の符号/大きさ、接触pair数、`max penetration`、`p_spring`、ばね参考仕事の正/負。
- 代表点および接触領域の`Δu_open`、`gap`、`Amin`、接触位置`x,z`。ただし代表点の`Δu`を**別位置の実際の接触仕事の代用品にしない**。
- モードごとの`Q_spring`符号、`Δq`符号、その積の符号。ベクトル基底の符号自体は任意なので、`Q`単体の符号に物理的意味を置かず**`QΔq`で比較**。
- 荷重と実運動の時間整合：採用予測接触荷重が`t_n`で評価されたのか、`q_{n+1}−q_n`は最終Newmark確定解か、**接触判定の反復が最終変位に完全に一致しない**可能性がある点を明記。

**必須判定**：「左のばね仕事が正、右が負」になるのは、(i)どの時刻/領域/モードの正負の総和から生じるのか、(ii)持続的な符号差か、少数イベントに左右されるか。結果が相殺である場合は正寄与と負寄与を並べ、単一の「左ばねが駆動した」という表現を避ける。

### A3. 左右の相互作用としての検査

同一接触ペアの左右力は反対方向でも、**各側の`F·Δu`は一般に等しくない**。以下を併記：

- `W_spring,L`、`W_spring,R`、**両側和**`W_spring,L+W_spring,R≈−0.03078 mJ`、および各側の正/負内訳。左右反対符号の`0.4 mJ`規模の仕事が**全体としてほぼ相殺**されているか（数値的な表現）を、窓依存性と時刻別同時性で確認。
- 同じ`[0.30,0.50)`の`W_damp,L+W_damp,R≈−1.32743 mJ`との比較。「ばねの両側和が小さい」と「ばねが保存力である」は**同値ではない**。
- ペア対応の相対変位が保存されていれば`F_pair·(Δu_R−Δu_L)`との照合が可能。ただし**保存されていないペア別情報を後から作らない**。節点分配・ペア接触位置移動を考慮できない場合は`NOT_IDENTIFIABLE`とする。
- 右小振幅とばね仕事の関係は**同時観測の機構候補**に留め、ばね仕事の左右差の81.4%を**振幅差の因果寄与率**と言わない。

### A4. モード寄与・流体との照合

`|W_spring|`が大きいモードと`|W_damp|`が大きいモードの上位を抽出。既報の注目モード（左5/7/12、右4/7/9等）と比較。たとえば既報：
- L mode 12: spring `+0.3151904` mJ、damp `+0.08509109` mJ
- L mode 5: spring `−0.2728333` mJ、damp `−0.2252826` mJ
- R mode 7: spring `−0.2215505` mJ、damp `−0.2892881` mJ

**モードごとに符号が混在するため、左の正味ばね仕事が正でも「左の全モードがばねから仕事を受ける」とは言えない**。`MAC`が曖昧なモードを対称条件と同じ番号で機械的に比較しない。対称12/12の成分別データがないため、対称との差は総接触仕事と振幅までに限る。

必要なら前回のraw流体仕事・モード分散との**併記**を行う。ただし流体`W_raw`と接触参照`W`を差し引きして**厳密なエネルギー収支**が成立するとみなさない。モードGram非対角成分や離散時間の違いを保留する。

## 4. 調査B：旧／新フルrunのbit差「最初の地点」を特定

### B1. **2つの異なる比較**を必ず独立に実施

**(i) 文字`dat`の差：** 9ファイルすべてを旧／新で読み、SHA256、行数、列数、各行の`time`/`step`の一致、異なる**セル文字列**の件数、浮動小数として解釈した値の`max_abs/max_rel`と初出stepを出す。**41セル**という既報値を再検算。ヘッダ/空白の差と数値文字列差を分け、全差分セルに「file, row, col, original, new, step/time」を付与。`airflow_vt.dat`の完全一致は陽性対照として記載。

**(ii) 生バイナリの差：** 旧・新`kanaya_diagnostic/modal_native.bin`を、それぞれの`run_metadata.json`に従ってmemmapで読み、**レコード構造/step/side/modeの完全整列**を確認してから`Q_pos, Q_neg, Q_fluid, Q_contact, q_n, qdot_n, Δq`の差を求める。**初出の相違step/side/mode/field**、そのstepで異なる項目一覧、差のmax_abs、max_rel、必要ならULP（符号跨ぎ・±0/NaNの扱いに注意）を算出する。

**bitwise**・**numeric equal**・**format equal**を区別。CSVテキストが同じでも内部値が違う場合がある。前回`q≈6.17e−15`等の最大差があるため、**数値差ゼロと断定しない**。

### B2. 初発差からの経時変化を追う

- **全stepの差の時系列**：`max_m|Δq|`、`max_m|Δqdot|`、`max_m|ΔQ_fluid|`、`max_m|ΔQ_contact|`（左右別）、既存`contact_regions.csv`の接触pair数/反復回数/停止理由、`flow_geometry.csv`の`Amin,Ug,Pg`等が比較可能な範囲で一致するか。
- 最初の内部差ステップを`n0`とし、`n0−2 ... n0+5`等の周辺で、流体→接触判定→モード力→qのどこに先に差が現れるかを**同じsamplingと記録段階**で追う。保存されていない中間値の初発順序は判定しない。
- 41セルの文字差は数値差のうちどの時刻・出力列・丸め閾値に発生したか。`0.001 Pa`や`1e−6 mm`の「表示単位の境界」を超えた可能性を定量的に述べる。**真の内部軌道が少し異なる**ことと**印字セルが少数だけ異なる**ことは両立する。
- 200-stepスモークが合格していても「201 stepから必ず差が始まる」とは限らない。**短縮runは本番と出力分岐・終端ガードが違う可能性**がある。ログ・元runの実行バイナリ/コンパイルフラグ/変数初期化・OpenMPを確認するが、**新しいソルバ実行による再検証はしない**。

**原因の分類（複数可）**：
1. `FORMAT_THRESHOLD`：元/新内部値がごく近く、テキスト出力丸めの境界に位置する（**内部値の差があるなら`FORMAT_ONLY`とは呼ばない**）。
2. `NUMERIC_TRAJECTORY_DELTA`：`q/Q`など内部で差が観測される。初発時刻/変数と大きさを記録。
3. `METADATA_OR_BUILD_DIFF`：旧／新バイナリSHA、ソース/コンパイル/ビルド差は確認済みか、パラメータ/入力SHAは一致したか。**バイナリSHAが異なること自体は「差の原因がobserver」との証明ではない**。
4. `CONTACT_EVENT_DIVERGENCE`：差の発生付近で接触有無・採用反復・ペア数が異なる証拠があるか。
5. `UNKNOWN`：保存された観測量だけでは発生源を特定できない。

### B3. bit不一致を受けた、結論の出し方

旧runと新runの`SHA256`非一致という事実は固定。**勝手に合格閾値を変えない**。一方、次の**別の評価**を可能な限り報告：

- `trajectory_bitwise_identical=false`
- `raw_work_near_equal`：同窓`W_contact_total`の旧新差・相対差と、左右差`W_R−W_L`に対する比。**旧新差が左右差より圧倒的に小さいこと**は観測値の頑健性の根拠になり得る。
- `new_run_component_split_algebraically_valid=true`（既報内部のQCが再確認できる場合）
- 旧新の**時間点ごと**の総接触仕事・累積仕事の差が新成分分解と比べ小さいか。最大ステップ差だけで判定せず、時間窓・積算の頑健性を測る。
- `component_split_extrapolates_to_old_trajectory=UNPROVEN`。新runの成分仕事はあくまで**新runの採用荷重の分解**であり、旧runの厳密な成分分解と呼ばない。

**解釈ゲートの扱い**：元仕様の`FAILED_QC`は変更せず、**「新run内部の記述結果と、旧runと定量的にほぼ一致する総仕事を踏まえた暫定説明」**という独立のエビデンス段階として報告してよい。**原因や因果を確定したとして`Hdamp/Hspring`をPASSに書き換えない**。

## 5. 結論としてまとめる内容（報告書の冒頭にまず書く）

ユーザーが求める「一旦、振幅差の結論」を**再計算・捏造なし**で出す。以下は**現時点での暫定文章**であり、今回の後処理で支持/不支持と不足データを加えて更新すること。

> **暫定結論（観測事実）**：Bodyを左右12/6 kPaとした900 Pa条件では、柔らかい右声帯の振幅は硬い左声帯より小さく、代表点R/L=0.302、表面全体R/L≈0.491であった。対称12/12では左右振幅が一致し、非対称化では左の振幅増加と右の振幅減少が同時に起きた。代表点では左のモード間共分散が正、右では負となり、局所振幅差が増幅された。

> **暫定結論（機構候補）**：同じ900 Paでも平均壁面流体荷重は左右でほぼ等しく、モード応答と接触を通じた仕事配分が左右で異なる。新12/6 runでは、右側の負の接触参考仕事の63.2%が速度依存項である一方、左右の接触参考仕事差の約81.4%は**左正・右負のばね仕事の差**から生じた。このばね仕事の左右符号差の時間/空間/モード内訳が、今回の後処理で重点的に評価すべき点である。

> **限界**：流体仕事はraw値であり厳密な動的励振仕事ではない。接触の負の参照仕事をそのまま不可逆散逸とみなせない。旧runとのフルbit一致は不合格で、新runの成分内訳が旧軌道の厳密な内訳とは認定できない。**したがって「右の振幅が小さい原因はばね仕事である」「ダンパーが振幅差の18.6%を説明する」とは結論しない。** 未同定の因果は別の対照実験/再現試験が必要である。

最終版`report.md`では暫定文章に対し、**ばね仕事が符号を反転させる主要イベント・領域・モードが実際に特定できたか**、**bit差の初出と最も具体的な原因候補は何か**を追記し、仮説ごとに`OBSERVED / CONSISTENT_WITH / NOT_ESTABLISHED / NOT_IDENTIFIABLE / FAILED_QC`を付す。

**誤認禁止**：
- 依頼文の「左小振幅」を確認済み事実として採用しない。
- 右側`damp/total=63.2%`と、左右差の`spring-share=81.4%`を混同しない。
- 仕事の代数的内訳（81.4%）を**振幅を決める原因の寄与率**と呼ばない。
- 左右ばね仕事の和が小さいことを、独立の接触ばねポテンシャル保存の証明としない。
- 「新旧の変位差がごく小さい」から「bitwise QC合格」と言い換えない。
- 対称12/12のばね/速度項の値を推測で作らない。
- 機構結論に向けて必要な信号が保存されていなければ、限界を書いて終える。

## 6. 後処理だけの実装仕様・テスト

推奨：`tools/amplitude_asymmetry/postprocess_contact_work_bitdelta.py`（既存`analyze_contact_components.py`や`compare_symmetric_asymmetric.py`の関数を再利用可能なら共通化）と`tools/tests/test_postprocess_contact_work_bitdelta.py`を追加。**Pythonのみ**で既存バイナリ/テキストをread-onlyで扱う。シミュレーション起動・コンパイル・C++診断改造は禁止。

CLI例（実際のローカル配置をCodexが確認）：

~~~bash
python tools/amplitude_asymmetry/postprocess_contact_work_bitdelta.py \
  --old-run <existing-12_6-original-or-old-diagnostic> \
  --old-diagnostic <existing-12_6-old-diagnostic> \
  --new-run <existing-12_6-component-diagnostic> \
  --previous-analysis <existing-contact-component-analysis> \
  --sym-analysis <existing-symmetric-comparison> \
  --output-dir <new-empty-analysis-dir> \
  --no-simulation
~~~

- `--old-run`と`--old-diagnostic`が別なら、**どちらが`dat`の比較元で、どちらが旧`modal_native.bin`の比較元かをmanifestに明記**。
- 出力先が存在する場合は上書き拒否、元ファイルのsize/sha256/mtimeを処理前後で検証。既存runに汚染を残さない。
- 標準ライブラリ＋NumPy/pandas/Matplotlibを既存環境に合わせて使う。巨大な配列は`numpy.memmap`とchunkで処理。入力binのsize/shape/dtype/endian/field一致を厳格にチェックし、NaN/Inf/非対応schemaは`FAILED_INPUT_QC`。
- 時刻、セル、モードを**名前/列名に基づき**整列。条件/窓不一致があればエラーとし、数値を推測して合わせない。
- datには`time`がないファイルもあるため、step番号/出力stride/元manifestから対応付け可能なら実施。**不明な行は時刻`UNKNOWN`にして保留**。違う頻度のサンプルを行番号だけで同時刻と仮定しない。
- 演算する全仕事はJ基準、表示mJ、元CSVの単位をmetadataから確認。`q`と変位`mm`の換算で1e3誤りに注意。
- 先行`report(5).md`の結果が出発点であり、今回の新しい図や判定に**まだない測定値を生成済みと書かない**。

### テスト必須（後処理コードだけの実行可）

1. 完全一致の合成`dat`と生バイナリ→差分0、初出なし。
