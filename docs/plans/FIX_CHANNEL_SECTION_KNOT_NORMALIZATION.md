### 極めて重要：現状コードとの整合性を最初に調べること

2026-10-20にGitHub mainで確認できる `ChannelSectionBuilder::build()` には、`std::sort(knots)` 後に：

```cpp
knots.erase(std::unique(knots.begin(), knots.end(),
    [](double a, double b) { return std::abs(a - b) <= cutTolerance; }),
    knots.end());
```

が存在し、`cutTolerance=1e-9 mm` である。

**このコードが有限値・昇順のknotsに正しく適用されていれば、隣接する残存knots間に`1.8e-15 mm`の差があるのは通常整合しない。** したがって「`std::unique`が単に効かなかった」と決めつけて同等の処理へ置き換えることは不可。実行したコードの不一致、計測箇所、配列の生成・書換え、バージョン差、検証ロジックをまず確認せよ。

ローカルの`channelSections.cpp`はGitHub mainや過去の仕様書と異なっていてよい。実際の作業対象は**Codexが操作するローカルのファイル**。

### A-2. 少量の一時診断で不変条件を調べる

`knots` について、以下を**重複除去の前後それぞれ**で検査する。`knots` は各x平面の左・右輪郭節点z座標、0.1 mm刻みz座標、`refHigh`から構築されているはず。

- 最小正の隣接差 `min_positive_dz`。
- `0<dz<=cutTolerance` に該当する隣接区間数と、その区間の `z0,z1,dz`（多くても最初の数個）。
- 異なる輪郭ノード（左右）のどのz値が、どう統合されたか。重要な場合のみ記録する。
- `knots`を用いた実際の積分ループが、検証した配列の同じスコープ・同じ版を参照しているか。
- `cutTolerance` が正で、場所によって異なる許容差を使用していないか。

長いシミュレーションの全ステップで標準出力しない。既存隔離診断の`/tmp`に失敗時だけ記録するか、小さな再現ハーネスを`/tmp`に作る。既存 `tools/run_channel_section_diagnostic.py` は`--run`でフル実行になるため、**勝手に実行しない**。

## 3. フェーズB：案②を最小実装

### B-1. 重複z分割点の正規化は一箇所だけ

同じ機能があちこちに存在しないよう、`ChannelSectionBuilder::build()`の`knots`準備段階で、明示的で検証可能な正規化を行う。

要件：

1. 各z候補の有限性を確認してからソートする。
2. 極近接した値を単一z境界にまとめる。原則 `cutTolerance=1e-9 mm`を維持し、**許容差を大きくして問題を隠さない**。
3. 単純な`std::unique`への同等置換を「根本修正」と主張しない。原因が既存コードとは違う場合、まず原因を直した上で分割点の正規化を明示する。
4. グループ化する場合は、チェーン状の近接値で統合幅が無制限に広がらないよう、**グループ先頭との差が`cutTolerance`以内**であることを条件にする。代表zは既存の候補値から採用し、架空の表面節点を作らない。
5. `refLow/refHigh`等の既存AP積分範囲を大きく変更しない。AP欠損領域に面積を補間しない。幾何頂点自体を移動しない。
6. 正規化後に **不変条件：全ての実際の積分区間について `z1>z0` かつ `z1-z0>cutTolerance`** を検査する。想定外の微小区間があれば、その場のデータを明示して失敗とする。検査は重いログではなく軽い条件分岐でよい。

一例（これだけでは、現行`std::unique`がすでに存在する原因は解決しない点に注意）：

```cpp
std::sort(rawKnots.begin(), rawKnots.end());
std::vector<double> knots;
for (double z : rawKnots) {
    if (!std::isfinite(z))
        throw std::runtime_error("nonfinite z knot");
    if (knots.empty() || z - knots.back() > cutTolerance) {
        knots.push_back(z);
    }
    // 近接zは既存候補の一つに統合する（連鎖的な無制限結合は禁止）。
}
```

境界を統合することで、選択線分端点の`yOnEdge()`の評価点が元の端点から微小にずれる場合がある。区間内点が実際に辺の開区間にあり、端点は丸め誤差相当の範囲でのみ評価されることを確認する。離れた位置への外挿をしてはいけない。

### B-2. 安全策と既存判定の維持

- `z1-z0 <= cutTolerance` の積分区間は**通常積分に渡さない**。理想はB-1で生成されないこと。残ったら「検証済みの真に微小な区間」であることを確認し、無条件にskipして正常扱いするのではなく、発生原因と除外量を把握する。
- 省略したz区間の累積幅 `total_discarded_dz` をテスト・失敗時診断で確認する。ゼロ幅を除いて、実質的な幾何区間が大量に消えるようなら正常終了させない。判定閾値はデータと許容差に基づいて説明する。通常ログを増やさない。
- `envelopeEdge()`の**有限幅区間内部での**本物の3枝以上の判定を残す。
- `validateContour()`の自己交差・分岐・複数連結成分検出を残す。
- 負の符号付きギャップは実接触として扱い、欠損・多重交点と混同しない。
- `yOnEdge()`に水平・極端に狭いz幅の辺が誤って渡ることを防ぎ、非有限値での積分を許可しない。
- **過去の別指示** `docs/plans/FIX_CHANNEL_SECTION_KNOT_INTERSECTIONS.md` に従って`envelopeAtKnot()`がすでに削除済みなら復活させない。未削除でも今回は主眼がknotsなので、除去・分岐判定の置換が必要な場合は当該過去指示と整合する最小変更だけを行う。頂点での交点数チェックを復活させて偽陽性を作らない。

## 4. フェーズC：軽量検証と合格条件

### C-1. 検証ケース

元の3D表面・輪郭・断面計算を大規模改変せず、短い単体ハーネス、既存診断JSONの再生、あるいは最小の既存テストで確認する。次の項目を必須とする：

| 検証項目 | 期待する結果 |
|---|---|
| 実際の報告値 `z=0.20514879039334014/0.20514879039334194` | 2点は正規化時に同一グループとなり、幅`1.8e-15 mm`の区間が積分されない |
| ほぼ水平辺を含む交線 | 正常な幅のz区間の内側包絡線が一意なら積分できる |
| 完全水平辺とz節点が一致する交線 | 点/線分の重なりに起因する偽の多重交点エラーが出ない（未修正の場合は別件として報告） |
| 通常の矩形ギャップ`h=H`, AP長`L` | `A=H*L`、`G3=H³*L`に一致 |
| z方向で符号が変わるギャップ | ゼロ交差で分割して正部分のみ積分 |
| 有限幅で本当に3本以上の異なる枝 | 従来どおりエラー（黙って最大/最小だけ採用しない） |
| 複数連結成分・自己交差 | 従来どおり検出 |
| 左右どちらかの輪郭欠損 | z区間を勝手につながず、AP被覆率に反映 |
| 普通の形状での修正前後のA/G3 | 正規化で意図的に捨てた極微小幅に見合う範囲の差のみ。数値と許容根拠を報告 |

`envelopeEdge()`が無条件に全枝を許容するような変更でテストを通してはいけない。
