## 1. 今回の新しい評価法の基本原則

### 1.1「全区間を探索する」と「全区間に必ずJitterを割り当てる」は異なる

- 評価窓`0.50–1.00s`の**全サンプルを周期候補探索・波形状態判定・図示の対象**とする。従来の「相関不足で中断したら以後の周期を使わない」という処理は研究用の新しい主方式に採用しない。
- 局所自己相関・周波数分布から`T0(t)`を推定し、各周期の**探索領域を予測**する。**Jitterの算出に使う`t_i`は、波形上に実在する極大・極小イベントから選ぶ**。`T0(t)`の予測時刻で`t_i`を置き換えたり、間に架空のイベントを挿入しない。
- 周期が不明・イベントの位相が決まらない場所は`UNRESOLVED`とし、どの時間がなぜ判定不能だったかを**全窓に対して記録**。短いUNRESOLVEDを統計から黙って除くのではなく、その時間割合と他の振動指標を出す。
- **A（同種の極大）とB（同種の極小）の両方を独立に追跡・評価**する。Aを主比較候補、Bを独立対照とし、A/Bが一致したから真の正解とはしない。零流量時の平坦な極小は`plateau`として時間範囲と時刻不確かさを別に記録。
- 強いサブハーモニクス、周期倍化、実際の無振動などで「同種イベントの基本周期」が定義できない場合は`PERIOD_AMBIGUOUS`または`APERIODIC`。**その不規則性をJitter=0として扱わない**。

### 1.2 固定する方法と変更する方法

- 変更しない：`Ug`入力形式、dt/step時刻変換、波形の生データと補間、Jitter local/RAP/PPQ5の数式、CPP算出定義、従来結果と`--reanchor-policy legacy/recover-rejected`。
- 新規：**`--tracking-method global-cycle`**（名前は現行CLIに合わせてよい）で、局所ACFを使った**全窓候補検出＋系列全体の最適化**。旧追跡器はベースライン比較に残す。
- 必須の制御：`--input`、`--dt`、`--start`、`--end`、`--out-dir`、`--case-id`、`--tracking-method`、`--threshold-profile`、`--manual-events`、`--self-test`。解析パスをコードに固定しない。
- Pythonソースは**できる限り既存`tools/analyze_airflow_metrics.py`の1ファイルで完結**。新規ライブラリ・不要な環境は増やさず、`numpy/scipy/matplotlib`等の既存依存を利用。

## 2. Phase A：局所基本周期の推定と全窓の周期予測

1. `Ug(t)`のDC/ランプを評価窓と切り分け、`[0.50,1.00)`全体に対して**局所ACF**とスペクトルを求める。ベースは`fmin=60Hz, fmax=400Hz`、ACF窓`100ms`、hop`20ms`、補助的に60/140ms窓の感度も検証。
2. 各局所窓で`T0`、信頼度`R(T0)`、`T0/2`・`2T0`候補、波形形状の適合を保存。低信頼や2倍周期競合なら**一意のT0を確定したふりをしない**。
3. 補間した`T0(t)`は、**次イベントを探す領域の中心・幅**としてだけ使う。局所周期を滑らかに補間したものを真の周期列と認定しない。
4. 既存追跡器の高信頼イベントをアンカー**候補の一つ**として利用してよいが、**必ずそれを採用する固定seedにしない**。全窓最適化では旧ピークの誤採用も訂正可能にする。
5. 分断地点では、前向き・後ろ向き双方の情報と局所ACFを考慮し、途中の候補を再利用する。**中断点を越えられないことだけを理由に、その先の明確なイベントを捨てない**。
6. `local_period_candidates.csv`と`acf_timeline.png`に`t,T0候補,confidence,倍周期候補,評価可否`を保存。

## 3. Phase B：波の「上下」を利用した極大・極小イベント候補の生成

### B1. 局所振幅を使う（剛性条件による流量レベルの違いを吸収）

予測周期周辺の局所窓`W_i`（最初は`±1.5T0`、最低2～3周期に相当する幅を確保）で、

\[
A_{\rm local}(t)=P_{95}(Ug[W_i])-P_{5}(Ug[W_i])
\]

を算出。候補`j`のprominence`p_j`と、候補の前後にある谷～山の局所振幅`\Delta U_j`を求める。

- ピーク候補の主フィルタは**`p_j/A_local≥θ_p`**。`θ_p`の候補値`[0.03,0.05,0.08,0.10,0.12,0.15,0.20]`。
- 「波として認識できる上下動」の補助閾値`\Delta U_j/A_local≥θ_A`。候補値`[0.03,0.05,0.10,0.15,0.20]`。`θ_A`は**イベント存在の強さ**の判定に使い、**振幅の小さい周期を除外しやすい選択バイアス**が発生することを明示。十分な局所振幅がないときは比が不定なのでフラグ。
- 数値ノイズ床は局所first-differenceのMADや元データ精度から定量化し、**物理的根拠なく固定の大きなm³/s閾値を設定しない**。
- 既存のglobal`P95−P5`に対するprominence10%との比較も出す。局所閾値が極端に小さい場合にノイズを拾わないよう、最低絶対閾値の有無/影響を記録。
- `find_peaks(Ug)`と`find_peaks(-Ug)`の両方を使い、**全raw候補を削除せず、採否と判定根拠を保存**する。

### B2. 極大・極小の対応と時間精度

- A極大の候補ごとに前後の極小B、立上り/下降時間、谷～山振幅、局所二峰性、plateau有無を特徴量として計算。逆に極小Bの評価には前後のAを参照するが、相互に**強制的に正解イベントとしない**。
- **1つの流量パルス内の二次極大を異なる周期として採用しない**ため、局所盆地/反対極性イベントの境界情報を利用。二次峰の疑いがある場合は候補として保全し`SECONDARY_LOBE`を記録。
- 零流量で複数サンプルにわたり平坦な極小は、plateau開始・終了時刻を記録。極小時刻は代表時刻（例えば中央）と幅`uncertainty_s`を併記し、BのJitterが時刻代表点に敏感なら**Aを優先して評価する**。plateauを「精密な点イベント」と扱わない。
- 3点放物線補間ON/OFFを同一イベントIDで比較。予測`T0`の時刻へのスナップ禁止。
- `event_candidates_all.csv`にcase/phase/raw-index/time/prominence/local amplitude/peak-trough amplitude/plateau/shape correlation/rank/QCを保存。

## 4. Phase C：全窓のイベント系列を最適化し、周期飛ばしを防ぐ

**実装方式：候補イベントを節点、合法な隣接周期を辺とする有向非巡回グラフ（DAG）/動的計画法（Viterbi等）**を推奨。既存の順次greedy追跡だけに依存しない。単一Pythonファイル内に実装。

- 候補の`node`特徴：`prominence/A_local`、`\Delta U/A_local`、前後の谷/山整合、テンプレート形状、局所ACF信頼度、局所二峰/plateau。
- 2候補`i,j`の`edge`：正の実時間差`Δt=t_j−t_i`、局所`T0((t_i+t_j)/2)`との比、形状相関、同じ位相（同種極大/極小）の連続性。初期探索域は`[0.55,1.65]×T0_local`とし、厳格従来`[0.65,1.45]×Tref`とも感度比較。**単なる周期予測差の最小化を強い目的関数にしない**（真のJitterを抑制するため）。
- 予測1周期あたり**0、1、複数の候補**があり得る。候補が複数の場合、波形特徴、同位相、前後の系列の整合を総合し、全体として最尤のイベント経路を選択。イベントを1周期窓に一つ「必須割当」しない。候補ゼロは`UNRESOLVED`。
- 1つの物理パルスに属する2峰の両採用、1.8～2.2倍周期間隔を通常の1周期として接続、異なる位相候補への切替、同じピークIDの重複採用は禁止/警告。**2Tの可能性は診断として残し、欠けたイベントを架空に補完しない**。
- 不安定な波でも全窓を走査できるよう、連続追跡が失敗した場合は**`UNRESOLVED`状態での再開を許す**。前後の別segmentのイベントを無理に直結しない。始点/終点の不確実性も保存。
- ノードとエッジの重みは**暫定の事前固定値**（初期値を`TRACKING_CONFIG`に書き、CSV/JSONに保存）。探索後にJitterが都合よく小さくなるよう重みを選ばない。各候補のスコア内訳を必ずCSVで監査可能にする。
- 1番と2番の経路が近い場合、単独の強制確定は避け、**`path_score_margin`、`alternative_event_times`、`AMBIGUOUS_ASSIGNMENT`、推定信頼度**を報告する。差が小さいときの候補選択によるJitter幅も感度評価。
- `global_events_A.csv`・`global_events_B.csv`・`global_periods_A/B.csv`・`unresolved_intervals.csv`・`candidate_score_audit.csv`を出力。**全窓のすべての時刻が「採用周期の内側」「未解決」「明示的窓端」のいずれかに分類**されるようにする。
- 処理時間/メモリが肥大化しないよう、局所時間窓で候補edgeを制限し、全候補数・探索状態・計算時間・必要な上限処理を記録。閾値を変えても結果が再現するよう決定論的tie-breakerを採用。

## 5. Phase D：閾値の調整と全窓の信頼性評価

**比較するのはJitter最小値ではなく、イベント検出の妥当性と再現性**。研究対象の不規則波形を除外しないことを評価軸に含める。

### D1. 比較する設定

- `θ_p`: 3, 5, 8, 10, 12, 15, 20%（局所prominence）。
- `θ_A`: 3, 5, 10, 15, 20%（局所波形の上下動）。
- 局所ACF窓: 60, 100, 140 ms（hop 20ms）。
- edge時間探索範囲: `[0.55,1.65]T0` と `[0.65,1.45]T0`。
- 形状相関の有効閾値（採否・confidence）：`ρ=0.50,0.55,0.60,0.65,0.70`（これを固定のhard gateとして新アルゴリズムにそのまま課す必要はない）。
- 計算量が大きい場合は、**主設定と一因子変更を先に評価し、効果の大きい組合せだけ追加**。何を省略したか明記。
- 全閾値設定は**r0.25とr0.30で共通**。研究条件ごとに「最もきれいに見えるJitter」を与える別設定を選んではならない。
- 将来の他剛性比に備え、設定profile一式を`summary.json`や`threshold_profiles.csv`に保存して固定できるようにする。

### D2. 数値評価・採用基準

全設定で：
1. A/Bのイベント数、対応ID一致率（±50/100/150µs）、局所周期とACFの一致、二次峰への位相移動率、明らかな2T跳躍、閾値感度。
2. **time_coverage**（検出した有効周期で被覆された時間）、`unresolved_time_fraction`、`ambiguous_time_fraction`、振幅があるのに追跡できない時間の割合。
3. Jitter local/RAP/PPQ5：**`longest_legacy`、`recover_rejected_pooled_v2`、`global_cycle_estimated`**を区別。**`global_cycle_estimated`のうち自信の低いイベントを含む推定値は`PROVISIONAL`**。
4. フル窓を探索できているか（分類時間が窓全体を100%カバーするか）は**イベント追跡率と別指標**。
5. CPP（既存定義のまま）、CPPフレーム数/警告、ACF信頼度、周期倍率候補なども一緒に比較。
6. 曖昧なイベントが複数あるとき`best path`だけでなく**上位候補への選択変更感度**を出し、Jitter/RAP/PPQ5の頑健性を検証。根拠不明なJitter推定区間を単にゼロ埋めしない。
7. **使用周期数・平均周期・隣接周期差項数・RAP/PPQ5項数・各指標に使った時間比率**を必須報告。`pooled_v2`と同様、境界を跨ぐ差分は禁止。

**設定採用の順序**：
- まず既存検出器との同じ高信頼区間でイベントID整合を検証。
- 次に**旧途切れ区間で新たに得たイベントを全件拡大図で精査**。
- その後、目視で正解イベントが確定した場合だけ`precision/recall/F1`、時刻誤差、誤周期率で閾値を判断。
- 人手未確定なら**暫定推奨profile**とし、`CALIBRATION_PENDING_MANUAL`を表示して「最適化完了」と呼ばない。
- 主profile選択の根拠は**イベント整合・位相維持・誤接続回避を優先**し、Jitter最小化・最大化・見かけの被覆率最大化を目標にしない。可能なら0.25/0.30で注釈区間を較正・保留（holdout）に分け、同じ注釈点で過剰調整しない。

### E2. 手動注釈の既存機能を再利用する

- 現行の`manual_review_index.csv`、`manual_events_template.csv`、`--manual-events`、マッチング/TP/FP/FN/F1、100µs基準（50/150µs比較）を再利用。
- `case_id,phase,event_time_s,confidence,reviewer,notes`の形式を維持。ユーザーが極大A・極小Bを見て**同位相のイベント**として注釈できる図を生成。
- **重点：これまで追跡できなかった区間**を必須review対象とし、対照として容易な区間も含める。古いイベントIDではなく時刻・元データIDで一致を取る。
- 手動正解が揃う前に正確度を断言しない。自動検出との一致を「人手の真値」と偽って計上しない。注釈時刻の単位・並び・重複・plateauの幅・uncertainを検査。
- 人手イベントが得られたら**同じ絶対時間窓・同じphase・同じ有効周期でのJitter差**、間違えた候補位置、漏れ、2T飛ばしを確認する。未提出なら最終レポートで`PENDING_MANUAL_ANNOTATION`。

## 7. テストと現行法との比較（必須）

既存`--self-test`に合成テストを追加する。新たなテストファイルやpyスクリプトを原則増やさない。

1. **周期一定・単峰**：解析窓全体でイベントが1周期に1回、Jitter≈0。
2. **真のJitterを既知に設定した波形**：局所`T0`とevent seriesを比較し、DP最適化が周期のばらつきを人工的に抑えない。既知値への一致を測る。
3. **1周期内に大小2峰**：同一周期内の二次峰を誤って独立周期にしない。
4. **極小plateau/零流量閉鎖**：最小値イベントの時刻が一意でない場合のuncertainty表示。Bが「高精度Jitter」と誤認されない。
5. **振幅変調・局所形状の急変・多峰・低振幅**：時刻精度と条件ごとの見逃し・誤採用を検証。
6. **周期倍化・subharmonic・真の無周期**：`T0/2,T0,2T0`の曖昧さを出し、無理に1:1周期へ分割しない。
7. **候補なし/再アンカーが必要な空白・窓端**：全窓は探索済みと記録、UNRESOLVEDと境界条件の理由を記録。物理的な波形が存在するなら、再開後は末尾までイベント探索を続行。
8. **閾値変化**：profile違いで同じ位相のイベントが保持できるか、Jitterの期待値/欠測率を確認。
9. **元のrecover-rejected回帰**：baseline指標・採用イベント・`CPP`一致。旧方式の出力を上書きしない。
10. **時刻解像度・1step/5step**：実stride1の参照がない場合、`NOT_AVAILABLE`。合成stride1から5step間引きした変化はテスト可能。補間は同イベントIDに対してのみ比較。
11. **総合**：Jitter/RAP/PPQ5の区間境界またぎ差0、候補ID重複0、出力manifest、CSV列/単位、CLI、画像全窓カバー、一時ファイル後片付け。

**合成テスト通過と、人間が実データ全イベントの正解を確認したことは区別**。推定イベントの性能を人工信号だけで保証しない。

## 8. `analysis_runs`の整理・削除（ユーザーの明示希望）

**ユーザーは「必要ない・もう使用しないanalysis_runsのディレクトリは削除」と依頼している。** ただし、このディレクトリ内には元流量・基準データ・検証用の過去ログが混在するため、**全削除・名称だけの推測で削除してはならない**。今回の新規解析と回帰確認が済んでから、**不要と検証できたディレクトリだけ実際に削除**する。安全性が確認できないものは保持し理由を報告。

### 8.1 最初に棚卸し（実行前dry-run）

- `analysis_runs`直下と必要な下位ディレクトリの**名前、実パス、サイズ、ファイル数、作成種別、用途、参照元、内容hash/重複の有無**をリストアップして`cleanup_inventory.csv`と`cleanup_dry_run.md`へ保存。
- `AGENTS.md`、README、`.gitignore`、過去計画書、実装コード、実行スクリプト、Git tracked状態、最新レポート/figureの相対リンク、既存manifestsを検索して、**参照されるディレクトリを検出**。
- 保護対象（削除しない）：
  1. **`analysis_runs/manual_run_archive/r0p25_...`、`r0p30_...`とそれぞれの`snapshot/dat/airflow_vt.dat`**を含む元入力一式。これらはこの2条件の一次データ。
  2. 再解析に必要な元パラメータ/manifest、モード・流量・圧力等の一次データ、ユーザーが明示して保管しているrun、未完了のrun、別研究に関連するデータ。
  3. 新しく作る`analysis_runs/airflow_global_cycle_validation_20261106`と**新旧baseline・手動レビュー図/テンプレート・注釈済みCSV・manual validation・comparison report・回帰検証記録**。
  4. ユーザーの未コミット変更、Git管理下のファイル、外部参照が確認できる内容、用途不明または一意に再生成できないデータ。
  5. 既存の`CPP`比較・過去の`report(9)`検証に必要な数値・metadata/hashと、比較図（少なくとも新レポートに完全な根拠を残す）。
- 削除候補：**この解析作業で生成された使い捨てテスト・空ディレクトリ・完全な重複一時結果・新しい統合レポートで代替できることを確認した古い中間キャッシュ**。候補ごとに、何に置き換わり再生成可能かと、削除根拠を記録。**別の剛性比や条件の唯一のsimulation結果は削除禁止**。
- 古い`airflow_metrics`や`tracking_diagnostics`などの名前だけで不要と断定しない。比較のため現役なら保持。新レポートを生成し、少なくとも数値・元ソース・参照元の移行を確認したものだけ候補にする。

### 8.2 安全に実行する

- 最初に**dry-run一覧を確定**。`SAFE_TO_DELETE`と`KEEP/UNKNOWN`を区別。**SAFE_TO_DELETEだけ同じ実行で削除を実施**し、`cleanup_deleted.csv`に相対パス/サイズ/hash/理由/日時/解放容量を記録する。保留分は`cleanup_kept.csv`に残す。USER_CONFIRMATION_REQUIREDのものは削除しない。
- 削除対象の解決済みパスが**厳密に`<repo>/analysis_runs/`配下**にあり、`analysis_runs`自体でなく、symlink/`..`で外へ抜けず、Git trackedでもなく、保護リストと重複しないことをコードで検査。**汎用的な`rm -rf analysis_runs`、`git clean -fdx`、無条件recursive deletionは禁止**。
- 削除処理はディレクトリ単位・許可リスト単位で記録。元流量`airflow_vt.dat`を含むディレクトリ、hash一致していない解析成果物、一意の患者・研究・学会データは削除禁止。
- **今回必要な解析・図が全部完了する前に、既存結果の整理を始めない**。削除後、保護した2本の`airflow_vt.dat`のSHAと、新`summary.json`・レビュー画像・旧baseline再現をもう一度検証する。
- 安全に断定できる削除候補がゼロなら**ゼロ件削除と理由を正直に報告**。ユーザーの要望を理由に不明データを推測で消すより、この方が正しい。不要ディレクトリを確認できた場合には削除を先送りせず、実行する。
