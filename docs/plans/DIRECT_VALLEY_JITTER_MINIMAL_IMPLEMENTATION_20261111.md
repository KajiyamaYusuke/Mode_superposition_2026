## 0. 目的と設計原則

現在の簡易固定周期解析では、ACF→初期谷3点→固定周期区間→1区間1 Main→Main-to-Main下降交差→3%/5% Jitterという流れを使う。しかし、

- 固定周期と実際のパルス間隔のわずかな差が積算し、境界が波形の山側へずれる。
- 独立したパルスが同じ固定区間に2つ入っても、Mainは1つしか採用されない。
- 低流量谷が区間境界やMain選択の影響で見逃される。
- 各Mainピークの3%/5%閾値はピーク流量が小さいと絶対流量の閾値も下がり、ほぼ同じ絶対流量の谷でもイベントが欠落し得る。

この問題を切り分けるため、**固定周期区間およびMain/Secondary選択を一切経由しない「実流量の局所極小の直接検出」を、独立した比較方式として実装する**。

目的はJitterを小さくすることではない。波形に実在する谷を、全ケースで同一の事前固定ルールにより再現可能に抽出し、谷間隔の不規則性を測る。

今回の方式は「谷時刻Jitter」であり、声帯接触開始・厳密な声門閉鎖時刻のJitterと同一視しない。浅い谷も検出対象になり得る。

## 3. 方法の全体像

1. 元の時系列 time, Ug を読み込む。dtは**保存行の間隔ではなくソルバ1ステップの秒数**。時刻は整数ステップ×dtから作る。
2. 解析窓 [start, end) の前後も含む元データ上で局所極小候補を取得する。
3. **候補谷の両側で流量がどれだけ回復したか**（谷prominence）と、近傍の局所振幅幅を比較する。
4. 基準10%に合格した候補谷をすべて、時刻順にイベントとして採用する。5%・15%は閾値感度比較として同時評価する。
5. 採用イベントをソートし、**すべての隣接イベント間隔**を使ってJitter local、RAP、PPQ5を計算する。
6. 谷候補・採否理由・間隔・波形上のマーカーを保存し、波形と対応するかを検証する。

**禁止**：ACF周期で谷を等間隔に並べる、1周期1谷へ制限する、最小イベント間隔で削除する、Main-to-Mainへ戻す、Jitterを下げるために波形・イベントを補正する、見つからない谷を補間する。

## 4. 谷候補の検出：SciPyのprominenceを活用

元の生流量 Ug の符号を反転し、次のように候補を取る（概念コード）。

~~~python
valley_idx, props = scipy.signal.find_peaks(
    -flow,
    prominence=0,
    plateau_size=(1, None),
    wlen=local_window_samples,
)
~~~

- 谷は -Ug の局所ピークに相当する。
- 谷のprominenceは、谷から見た左右の回復の**小さい側**に相当し、両側に十分な流量の上昇が必要になる。
- wlenは局所回復を計測する窓。**初期案は全幅30 ms**（入力の実保存サンプル間隔に換算して奇数に丸める）。最初の実装では --local-window-ms 30 の1引数だけでよい。
- 固定30 msは実験上の暫定設定で、ACFの推定周期・位相には依存させない。これによりACFの2倍周期誤推定や時間ドリフトがイベント採否へ伝播しない。
- full-window幅30 msが波形の特性（例：長周期）に合わないケースでは、その限界を診断・報告する。勝手にケースごとに最適化しない。
- **候補には距離（distance）制約を使わない**。短い間隔でも実在する独立パルスなら複数谷を拾えるようにする。

SciPyの-prominenceを使用すれば、谷の前後の回復判定を別途複雑に実装する必要はない。さらに「数ms以内なら合体」といった時刻ベースの後処理も導入しない。

## 5. 谷の採用：浅さと微小振動を分ける

各候補谷 i の局所振幅幅を、候補時刻の±15 msの原波形から

A_local,i = P95(Ug) - P5(Ug)

として計算する（窓端では取得可能な点を使い、窓が著しく不足するなら診断フラグ）。谷の突出度を P_valley,i とする。

主解析（10%）の採用条件：

P_valley,i >= 0.10 × A_local,i, かつ A_local,i > 0

感度比較として5%と15%も同じ候補・同じ局所振幅から算出：

P_valley,i >= 0.05 × A_local,i  
P_valley,i >= 0.15 × A_local,i

**重要な意味：**
- 谷の絶対流量が0に近いことや、Mainピークの何%かは採用条件にしない。浅い（流量が0まで落ちない）谷でも、両側への回復が十分なら採用する。
- 谷付近の小刻みな振動は、周囲の大きな変動に比べた谷prominenceが不足すれば不採用になる。
- 逆に小さくても明瞭な独立パルスは採用され得る。**どの谷が同一閉鎖過程の小振動か、全条件で自動判定できるという保証はない。**
- 局所流量変動が極めて小さい区間では相対閾値も小さくなるため、微小変動を拾い過ぎる可能性がある。判定が危うい波形・区間は図と候補表で確認する。初版で恣意的な絶対流量床やスムージングを追加しない。
- 閾値5/10/15%は**事前に固定した感度解析**。Jitter値を見て条件ごとに閾値を変更しない。
- 流量が負値でも生データを勝手に0クリップしない。

谷間の時間間隔が短いという理由だけで棄却しない。例えば2つの深い谷の間に明瞭な流量回復があるなら、以前の固定周期区間に同居していても両方を保持する。

## 6. 平坦な谷・時間定義

- 元波形に複数サンプル連続で**厳密に同一の最小値**がある場合、find_peaksの plateau 情報（left_edges/right_edges）を使い、その区間の**中央時刻**を代表谷時刻とする。
- 1点だけの最小ならそのサンプル時刻を用いる。
- plateau_samples、plateau_duration_ms、valley_flow を記録する。ほぼ等しいが厳密に等しくないサンプルを、独自許容誤差で強制的に平坦化しない。
- この時刻は閉鎖開始ではなく「最小流量区間の代表時刻」。ゼロ流量到達時刻とは区別する。
- 谷の時刻は今回、**補間・平滑化なし**。元データの保存刻み（典型50 µs）が非常に小さなJitterに与える影響をREADMEと結果の注記に残す。

## 7. 解析区間・端点

- 解析窓は既定 [0.50,1.00) s。イベントとして採用するのはその範囲内の谷のみ。
- 候補計算は、可能なら解析窓より前後を含む元の時系列全体を使用し、端点でprominenceを過小評価しにくくする。
- ファイル端で左右の回復が確認できない極小や局所窓が切れる候補は、曖昧であることを記録する。**時間窓端に人工的な谷を置かない**。
- 谷が0～1個ならJitterは算出不可（空欄など）。イベントが欠けても架空の時刻を挿入しない。
- 谷間隔が長短いずれでも自動除外・分割・補完せず、そのまま指標へ使用する。
- イベント時刻が重複した場合は不具合として検証し、無言で除外しない。

## 8. Jitter等の定義

イベント時刻 v1 < ... < vM から T_i = v_(i+1) - v_i（i=1,...,M-1）を計算する。N=M-1とすると、

Jitter local [%] = 100 × mean(|T_(i+1) - T_i|) / mean(T_i) （N >= 2）

RAP [%] = 100 × mean(|T_i - (T_(i-1)+T_i+T_(i+1))/3|) / mean(T_i) （N >= 3）

PPQ5 [%] = 100 × mean(|T_i - 5周期移動平均|) / mean(T_i) （N >= 5）

既存 period_metrics() と同じ式・サンプル数ルールを使用する。数値計算上の欠損間隔を補正しない。「谷間隔Jitter」と明示し、「閉鎖時刻Jitter」やF0 Jitterと無条件に呼び替えない。

## 14. 追加検証（2026-11-11）：ヒステリシスによる低流量エピソード統合

**背景**：第1版の直接谷検出（谷prominenceの5/10/15%比較）では、固定周期分割による取りこぼしは改善した一方、目視では「除外したい浅い谷」や「0流量付近の短時間の上下動」を複数イベントとして拾い過ぎる例がある。

**今回の追加仕様**：従来のprominence方式を削除・修正せず、別方式 **hysteresis** を比較実装する。前節までのprominence方式の記述は既存方式の仕様として残し、本節の条件は**hysteresis方式だけ**に適用する。優劣はイベント数やJitterの大小ではなく、元波形上のイベント対応で判断する。

### 14.1 定義：各ケースの共通流量基準と2閾値

各ケースの評価窓 [start, end) に含まれる生の流量 Ug から

\[
U_{\mathrm{ref}}=P_{95}(U_g),\qquad
U_{\mathrm{low}}=0.05\,U_{\mathrm{ref}},\qquad
U_{\mathrm{high}}=0.20\,U_{\mathrm{ref}}
\]

を設定する（**暫定設定**）。評価窓内では閾値を固定し、個々のピーク流量では再計算しない。 `U_ref <= 0` または非有限なら、当該ケースのhysteresis解析を **REF_UNUSABLE** として扱い、無理に閾値を生成しない。入力流量をクリップ・平滑化しない。

- **低流量区間への進入**：一度 Ug >= U_high まで回復したのち、Ug が U_low 以下へ下降したとき。
- **同一区間の継続**：Ug が U_high へ再び到達するまで。途中で0付近を何度上下しても**同じエピソード**にまとめる。
- **次区間の許可**：Ug が U_high 以上に戻ったあとだけ。単なる短時間間隔では統合しない。
- 「谷が浅い」かどうかは**谷の絶対高さ（本方式ではU_lowとの比較）**で決まり、従来のprominence方式でいう「谷の明瞭さ」と意味が違う。一定の絶対流量を全ケースで共通とする方式でもない。ケースごとにU_refを取ることによる条件間比較の限界を報告する。
- 目視上独立した弱い流量パルスでも U_high に達しなければ**統合され得る**。これは新方式の検出限界として必ず例示・報告する。

### 14.2 シンプルな状態機械（LOW/HIGHの2状態）

新規の独立関数（例： `detect_hysteresis_episodes(time, flow, low, high)` ）を追加する。意味の分かる数十行程度の**逐次スキャン**を基本とし、クラス・DP・ACF・Main/Secondary検出は使わない。

1. 最初は **UNARMED**。波形で `Ug >= U_high` を観測して初めて **ARMED** になる。データ冒頭が低流量なら、不完全な先頭エピソードをイベントとして数えない。
2. **ARMED** のとき `Ug` が `U_low` 以下へ下降したら新しい **LOW** エピソードを開始する。直前サンプルと当該サンプルによる線形補間で**最初の下降到達時刻** `entry_time_s` を求める。開始サンプルのindexも保持する。
3. **LOW** 中は最小生流量 `min_flow` とその位置を更新する。0付近での再下降・再上昇を独立イベントとして作らない。
4. **LOW** 中に `Ug >= U_high` を観測したらエピソードを確定し、回復時刻 `exit_time_s` を線形補間で求める。そのエピソードから**谷代表時刻 `valley_time_s` を1個だけ**保存する。次に **ARMED** へ戻る。
5. **LOW** がファイル末尾まで続き回復を確認できない場合は `INCOMPLETE_END` として記録し、主解析のJitterイベント列には含めない。評価窓末尾でLOW中でも、**元入力が評価窓より後まで存在する場合は、その実測データで回復を確かめてよい**。採用する代表時刻はあくまで [start, end) 内のものだけ。
6. 解析開始の手前にデータがある場合は、波形の前方も含めて状態を判定し、評価窓境界のエピソードの切断を避ける。回復確認できない前端エピソードは `INCOMPLETE_START` と明示する。

**谷代表時刻**は、LOW区間内の生流量の最小値を取る時刻。連続して同じ最小値が厳密に続くなら、その連続区間の**中央時刻**を採用する。離れた位置に同一最小値が複数ある場合は、まず最初の最小点を使用し `MULTIPLE_EQUAL_MINIMA` を記録する。不要なゼロ近傍許容差は設けない。生波形のサンプル時刻をそのまま使い、谷の時刻には補間・平滑化を行わない。

**重要**：`entry_time_s` と `valley_time_s` は異なる物理的指標である。前者は閾値下降到達（線形補間）であり、後者はエピソード内の実測流量極小（保存時刻刻み）。**両方を保存し、Jitterも別々に計算**する。少なくとも `valley` と `entry` の結果の違いを報告する。

### 14.3 既存prominence方式と厳密に分離する

- 従来の直接谷検出（prominence 5/10/15%）の結果、出力、デフォルトを維持し、新方式の導入で値が変わらないようにする。
- 可能なら既存の `tools/analyze_direct_valley_jitter.py` に `--method prominence|hysteresis` を追加する。CLI構造が複雑になるなら小さな別スクリプトでもよいが、共通のCSV読込・`period_metrics()`・manifest処理は無駄に複製しないこと。
- hysteresisでは **ACF周期、固定区間、Main-to-Main探索、谷のprominence、最短間隔の強制除外**を使用しない。
- 初版の閾値はlow=5%、high=20%。必要なら `--low-ratio` と `--high-ratio` を1つずつ設け、`0 <= low_ratio < high_ratio` を検証する。感度分析は例えば**high=15/20/25%を変更しlow=5%を固定**した別出力で実施する。**各ケースのJitter値に合わせて調整しない**。
- 方式を識別できるよう出力に `method`、`event_type`、`U_ref`、`U_low`、`U_high` を記録する。既存CSVの旧方式との共存を壊さない。手動比較できるよう比較表を簡潔に作る。

### 14.4 期待する最小出力

既存のmanifestで**全指定ケース**を一括解析する。既存の出力先・生データを上書きしない。

- `summary.csv`：case_id / method=hysteresis / event_type=valley または entry / events / Jitter / RAP / PPQ5 / 使用した3つの基準流量と各種診断。
- `episodes.csv`：1エピソード1行。entry_time_s、valley_time_s、exit_time_s、min_flow、duration_ms、min_flow/U_ref、状態フラグ。
- `periods.csv`：valley間隔とentry間隔を区別して全隣接間隔を保存する。長短間隔を恣意的に除外しない。
- 代表波形図：生流量、U_low、U_high、entry、valleyのマーカーを重ねる。**0付近の高速リップル・過剰検出された浅い谷・独立した弱いパルス**が分かる時間窓を優先。大量の重複図は作らない。
- 既存prominence方式に対して、**追加・消失・統合したイベントの具体例**を波形上で示す。個数比較だけで終わらせない。

### 14.5 絶対に確認する4種類の合成波形

数値が小さくなるかではなく、期待されるイベント**個数・時刻**が事前の定義と一致することをテストする。

1. `100 → 2 → 90`（U_ref=100の模式例）：low=5, high=20において**1エピソード**。
2. `100 → 25 → 90`：low=5まで下がらないので**0エピソード**。
3. `100 → 2 → 4 → 1 → 90`：途中の4はhigh未達なので**1エピソード**。谷代表は1の位置。
4. `100 → 2 → 35 → 1 → 90`：35がhigh以上へ回復しており、**2エピソード**。

上の100などは閾値説明用の模式値。**実装テストでは明示的に U_ref=100, U_low=5, U_high=20 を渡して状態機械単体を検証**する。短い谷間隔だけを理由に除外する条件を追加しない。

さらに、実データに対して以下を確認：
- 剛性比0.30 / 0.35 / 0.40 / 0.45 / 0.55 / 0.60、およびmanifest全ケース。
- 0付近で上下する部分が複数イベントにならないか。
- 既存prominence方式が拾った「浅すぎる谷」がlow未到達で不採用になるか。
- 弱い独立パルスがhigh未回復で統合される**副作用**がないか、あれば具体例を報告。
- 元データの保存刻みが谷時刻Jitterへ与える影響。特に非常に小さいJitter値には精度上の限界を記載。
- 既存prominence方式のイベント・集計結果に意図しない変更がないこと。
