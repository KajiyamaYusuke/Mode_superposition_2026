## 0. 目的と設計原則

現在の簡易固定周期解析では、ACF→初期谷3点→固定周期区間→1区間1 Main→Main-to-Main下降交差→3%/5% Jitterという流れを使う。しかし、

- 固定周期と実際のパルス間隔のわずかな差が積算し、境界が波形の山側へずれる。
- 独立したパルスが同じ固定区間に2つ入っても、Mainは1つしか採用されない。
- 低流量谷が区間境界やMain選択の影響で見逃される。
- 各Mainピークの3%/5%閾値はピーク流量が小さいと絶対流量の閾値も下がり、ほぼ同じ絶対流量の谷でもイベントが欠落し得る。

この問題を切り分けるため、**固定周期区間およびMain/Secondary選択を一切経由しない「実流量の局所極小の直接検出」を、独立した比較方式として実装する**。

目的はJitterを小さくすることではない。波形に実在する谷を、全ケースで同一の事前固定ルールにより再現可能に抽出し、谷間隔の不規則性を測る。

今回の方式は「谷時刻Jitter」であり、声帯接触開始・厳密な声門閉鎖時刻のJitterと同一視しない。浅い谷も検出対象になり得る。

## 3. 方法の全体像

1. 元の時系列 time, Ug を読み込む。dtは**保存行の間隔ではなくソルバ1ステップの秒数**。時刻は整数ステップ×dtから作る。
2. 解析窓 [start, end) の前後も含む元データ上で局所極小候補を取得する。
3. **候補谷の両側で流量がどれだけ回復したか**（谷prominence）と、近傍の局所振幅幅を比較する。
4. 基準10%に合格した候補谷をすべて、時刻順にイベントとして採用する。5%・15%は閾値感度比較として同時評価する。
5. 採用イベントをソートし、**すべての隣接イベント間隔**を使ってJitter local、RAP、PPQ5を計算する。
6. 谷候補・採否理由・間隔・波形上のマーカーを保存し、波形と対応するかを検証する。

**禁止**：ACF周期で谷を等間隔に並べる、1周期1谷へ制限する、最小イベント間隔で削除する、Main-to-Mainへ戻す、Jitterを下げるために波形・イベントを補正する、見つからない谷を補間する。

## 4. 谷候補の検出：SciPyのprominenceを活用

元の生流量 Ug の符号を反転し、次のように候補を取る（概念コード）。

~~~python
valley_idx, props = scipy.signal.find_peaks(
    -flow,
    prominence=0,
    plateau_size=(1, None),
    wlen=local_window_samples,
)
~~~

- 谷は -Ug の局所ピークに相当する。
- 谷のprominenceは、谷から見た左右の回復の**小さい側**に相当し、両側に十分な流量の上昇が必要になる。
- wlenは局所回復を計測する窓。**初期案は全幅30 ms**（入力の実保存サンプル間隔に換算して奇数に丸める）。最初の実装では --local-window-ms 30 の1引数だけでよい。
- 固定30 msは実験上の暫定設定で、ACFの推定周期・位相には依存させない。これによりACFの2倍周期誤推定や時間ドリフトがイベント採否へ伝播しない。
- full-window幅30 msが波形の特性（例：長周期）に合わないケースでは、その限界を診断・報告する。勝手にケースごとに最適化しない。
- **候補には距離（distance）制約を使わない**。短い間隔でも実在する独立パルスなら複数谷を拾えるようにする。

SciPyの-prominenceを使用すれば、谷の前後の回復判定を別途複雑に実装する必要はない。さらに「数ms以内なら合体」といった時刻ベースの後処理も導入しない。

## 5. 谷の採用：浅さと微小振動を分ける

各候補谷 i の局所振幅幅を、候補時刻の±15 msの原波形から

A_local,i = P95(Ug) - P5(Ug)

として計算する（窓端では取得可能な点を使い、窓が著しく不足するなら診断フラグ）。谷の突出度を P_valley,i とする。

主解析（10%）の採用条件：

P_valley,i >= 0.10 × A_local,i, かつ A_local,i > 0

感度比較として5%と15%も同じ候補・同じ局所振幅から算出：

P_valley,i >= 0.05 × A_local,i  
P_valley,i >= 0.15 × A_local,i

**重要な意味：**
- 谷の絶対流量が0に近いことや、Mainピークの何%かは採用条件にしない。浅い（流量が0まで落ちない）谷でも、両側への回復が十分なら採用する。
- 谷付近の小刻みな振動は、周囲の大きな変動に比べた谷prominenceが不足すれば不採用になる。
- 逆に小さくても明瞭な独立パルスは採用され得る。**どの谷が同一閉鎖過程の小振動か、全条件で自動判定できるという保証はない。**
- 局所流量変動が極めて小さい区間では相対閾値も小さくなるため、微小変動を拾い過ぎる可能性がある。判定が危うい波形・区間は図と候補表で確認する。初版で恣意的な絶対流量床やスムージングを追加しない。
- 閾値5/10/15%は**事前に固定した感度解析**。Jitter値を見て条件ごとに閾値を変更しない。
- 流量が負値でも生データを勝手に0クリップしない。

谷間の時間間隔が短いという理由だけで棄却しない。例えば2つの深い谷の間に明瞭な流量回復があるなら、以前の固定周期区間に同居していても両方を保持する。

## 6. 平坦な谷・時間定義

- 元波形に複数サンプル連続で**厳密に同一の最小値**がある場合、find_peaksの plateau 情報（left_edges/right_edges）を使い、その区間の**中央時刻**を代表谷時刻とする。
- 1点だけの最小ならそのサンプル時刻を用いる。
- plateau_samples、plateau_duration_ms、valley_flow を記録する。ほぼ等しいが厳密に等しくないサンプルを、独自許容誤差で強制的に平坦化しない。
- この時刻は閉鎖開始ではなく「最小流量区間の代表時刻」。ゼロ流量到達時刻とは区別する。
- 谷の時刻は今回、**補間・平滑化なし**。元データの保存刻み（典型50 µs）が非常に小さなJitterに与える影響をREADMEと結果の注記に残す。

## 7. 解析区間・端点

- 解析窓は既定 [0.50,1.00) s。イベントとして採用するのはその範囲内の谷のみ。
- 候補計算は、可能なら解析窓より前後を含む元の時系列全体を使用し、端点でprominenceを過小評価しにくくする。
- ファイル端で左右の回復が確認できない極小や局所窓が切れる候補は、曖昧であることを記録する。**時間窓端に人工的な谷を置かない**。
- 谷が0～1個ならJitterは算出不可（空欄など）。イベントが欠けても架空の時刻を挿入しない。
- 谷間隔が長短いずれでも自動除外・分割・補完せず、そのまま指標へ使用する。
- イベント時刻が重複した場合は不具合として検証し、無言で除外しない。

## 8. Jitter等の定義

イベント時刻 v1 < ... < vM から T_i = v_(i+1) - v_i（i=1,...,M-1）を計算する。N=M-1とすると、

Jitter local [%] = 100 × mean(|T_(i+1) - T_i|) / mean(T_i) （N >= 2）

RAP [%] = 100 × mean(|T_i - (T_(i-1)+T_i+T_(i+1))/3|) / mean(T_i) （N >= 3）

PPQ5 [%] = 100 × mean(|T_i - 5周期移動平均|) / mean(T_i) （N >= 5）

既存 period_metrics() と同じ式・サンプル数ルールを使用する。数値計算上の欠損間隔を補正しない。「谷間隔Jitter」と明示し、「閉鎖時刻Jitter」やF0 Jitterと無条件に呼び替えない。

## 12. 最低限のテスト

合成波形などで以下を検証する。期待する谷の**個数・時刻**を先に決め、Jitter値では採否を判定しない。

- 明瞭な深い谷と浅い谷：両方とも十分なprominenceなら採用。
- 深い谷底に振幅の小さい高速リップル：10%では本来の大きな谷を1つとして扱えること。
- 旧固定周期1区間内に2つの独立パルス：両方の谷を採用。
- 厳密な平坦谷（偶数点/奇数点）：中央時刻と幅が定義どおり。
- 周期間隔を少しずつ変えた波形：固定境界への累積ズレによる取りこぼしがない。
- 候補0個 / イベント1個 / 定数波形：例外なく算出不可を正しく出す。
- 5%で採用された候補は10%・15%の採用集合を包含すること（5% >= 10% >= 15%）。
- 全区間の間隔・RAP/PPQ5の項数と平均を独立に検算する。
- 可能なら既存簡易コードを無変更で実行し、既存3%/5%結果が不変であることを確認する。
