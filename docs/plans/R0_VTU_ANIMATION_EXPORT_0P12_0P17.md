# Codex指示：R0振動形状のVTU時系列エクスポート（追加連成計算なし）

目的：現行流体方式 R0（20 modes, Ps=1600 Pa）の左右3D声帯形状を、ParaViewで0.05 s分のアニメーションとして観察する。**R0を再連成計算せず、保存済みmodal-native履歴と元の形状・固有モードからVTUを再構成することを第一選択**とする。

## 1. 対象時刻・出力の仕様

- 対象：`R0_modern`（S2/S3や古い`kanaya_diagnostic.zip`の履歴と取り違えない）。
- `t=0.12000–0.17000 s`、フレーム間隔 **0.00050 s**（計101フレーム、約5.5振動周期）。実dtは`1e-5 s`なので50 step間隔。保存履歴の時刻タグを確認し、実在時刻のみ選ぶ。末端に実時刻0.17000がなければ外挿しないで実在する最終フレーム数を記録。
- 特別に **t=0.12480 s（最大面積付近）とt=0.12792 s（最小面積付近）**を元ステップから追加して、主時系列とは別の`keyframes/`へ保存。丸めた`area.dat`由来の極値と高精度診断の極値を混同しない。
- **左右両声帯の3D立体形状**（体積メッシュの座標、元のcell connectivity、点のfold id）を出力。第一候補は `deform_combined_*.vtu` に圧縮バイナリを用いる。容量が大きい場合、同一変位から**表示向けの表面だけを抽出したVTU/VTP**も作り、使用法と何が省略されているか明記。ユーザーが追加指定しない限り本番の全メッシュを全dtで出力しない。
- 出力先の例：`/home/kajiyama/code/kanaya_validation_archive/20261022_r0_s3/visualization/R0_0p12_0p17/`。既存ケース、archive、結果には追記・上書きしない。`frames/`, `keyframes/`, `README.md`, `metadata.json`, `frame_index.csv` を新規作成。
- ParaViewの時間認識用 `.pvd`（または対応する `.series` JSON）を生成し、**物理時刻[s]**を正しく関連付ける。ファイル名の連番を時刻と誤認させない。

## 2. 読み込み元と保護

1. `AGENTS.md` と直近の `comparison_report.md`、`output/kanaya_ablation_next/r0_aperture/report.md`、前回アーカイブのmanifestを確認。
2. R0時系列の候補：`/tmp/simulation-main-kanaya-ablation-20261021/output/kanaya_ablation/R0_modern/` と永続アーカイブ `/home/kajiyama/code/kanaya_validation_archive/20261022_r0_s3/previous/`。**保存済み `modal_native.bin` の実在・形式・20モード×左右・時刻対応をmanifest／既存解析コードで検証**。実データの所在は推測で固定しない。
3. 必要な元メッシュ、固有モードVTU、周波数、参照形状、左右鏡映・初期間隙・質量正規化は、R0の実効 `params.txt`／manifest／既存の `r0_aperture` 形状再生コードを優先して読み取る。**同名別ファイルを代用しない**。
4. ソース・入力・既存R0/S2/S3出力は保護。勝手な`git checkout`、`reset --hard`、`clean`、`stash`、`commit`、`push`は禁止。専用ツールと新規出力先だけ変更可能。実データが見つからない場合は、まず不足ファイルを報告し、出力を捏造しない。

## 3. 形状再構成の正確性

- 既存の**R0空間診断**が用いた、全20モードの座標再構成を再利用する。絶対座標／相対変位、元節点の順序、左右鏡映（特に`uy`）、初期gap、VTUモード成分の並べ替え、モードの質量正規化を再実装で勝手に変えない。
- 時刻`n`の**`q_n`**に対応する更新前/後の変形状態を特定する。出力時刻を`(n+1)*dt`と取り違えない。再構成点の`Points`とセルconnectivityの対応を保つ。
- 検証点：既存 `r0_aperture` の再生結果（`n=12792`、`x_min ≈ 9.967027 mm`、`Amin ≈ 0.0756281 mm²`）と整合を取る。ただしVTUの全体形状と50枚のx切断面から計算した最狭面積は別の量であることを理解し、必要なら**同じ実装の断面計算**を呼んで照合する。
- 可能なら参照VTU（過去の正規出力）との同一ステップ座標比較も実施。R0空間診断に記録された`q_15001`と更新後VTUの全節点差の最大`5.329e-15 mm`を参考にし、時刻・座標対応を確認する。
- 変形倍率は**1倍（物理量そのまま）**。VTU `Points`はmm。`fold_id`（0=left、1=right）、`time_s`、可能なら物理変位ベクトル[mm]を点データとして付加。点データの導入で座標・節点数・セルを変えない。
- **書き出しが物理計算を変化させないこと**。新規VTU出力のために再連成計算を行わない。出力ファイルサイズと所要時間を記録。

## 4. 高速化・堅牢性

- 既存環境のIntel `icpx`/Python/VTK系ツールの有無を調査し、最小の依存で対応。VTKライブラリが使用可能なら圧縮バイナリの`vtkXMLUnstructuredGridWriter`（または同等）を用い、ParaViewで開けることをテストする。新しい依存を勝手に大量インストールしない。
- モード形状・メッシュは最初の1回だけロードし、必要な101時刻だけ復元。**5000全ステップのメッシュ生成・全体再計算は禁止**。モード変位の合成はNumPy等でベクトル化し、メモリ・I/Oの利用実態を確認。
- 圧縮・書込CPUの並列化は、独立フレームに対する2～4ワーカーを候補にして実測で判断。CPUを多数使う目的は総所要時間短縮であり、闇雲な16スレッド/過剰な多重並列にしない。既存連成実行と同時に大量I/Oを発生させない。
- 大容量なら**視覚確認用の表面のみ101フレーム＋全体立体のキー2フレーム**を優先し、立体の全101フレームが必要な場合の追加手順を明示。採用方式・点数・セル数・容量・時間を報告。

## 5. 完了ゲートと使い方

- ファイル0件や最初の1枚だけで「完了」としない。時刻、101枚（実データの末端不足なら理由付きで実在枚数）、追加キー2枚、左右双方、幾何・セル整合、非有限座標無し、物理時刻系列の単調性をテスト。
- ParaViewで**時系列を開けること**を可能なら実際にテスト（ヘッドレスreaderでも可）。`Surface With Edges`または`Surface`、左右を分ける表示、Play操作、必要なら `Animation View`で0.12–0.17sの範囲に設定する手順を `README.md`に記載。
- `frame_index.csv`にはファイル名、時刻、step、節点数、セル数、サイズ、max displacementなどを記録。`metadata.json`に使用入力のSHA256と出力仕様を記録。
- 結果をアーカイブ内の永続場所に保存し、**絶対パス**を日本語で報告。ZIP等の軽量な配布物を用意する場合は容量を示し、既存の計算結果を含めない。

## 6. フォールバック

- `modal_native.bin`が見つからない、または20モードの`q_n`を取り出せない場合、**勝手にR0の再連成計算を開始しない**。まず欠損と必要な最短再計算条件を列挙する。再連成するなら既定modern／20モード／1600 Pa／ζ=0.06／同じ音響・接触・dtで、最初から`0.17 s`まで、VTUを`0.12–0.17 s`区間のみ指定の間引きで出すが、それには明示的にユーザーへ理由を知らせる。既存ケースを上書きせず、旧R0と`0.12–0.17 s`の物理出力一致を検証する。

最優先事項は **保存済みR0 modal履歴からの後処理だけで0.05秒の動画用VTU時系列を作ること**。振動数再推定・新たな物理パラメータ探索は行わない。
