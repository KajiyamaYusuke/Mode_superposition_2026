# Codex 作業指示：声帯振動シミュレータの機能棚卸し・検証用コード整理（Phase 1・2 のみ）

> **この文書をそのまま Codex に渡すこと。** 作業対象は Codex が開いている **実際のリポジトリ** である。以下の `*.cpp` に関する観察は、2026-10-14 時点で提供されたソース断片を確認した結果であり、実リポジトリの最新版や `include/`・`tools/`・`CMakeLists.txt` を網羅したものではない。**必ず現物を再調査し、異なる場合は実リポジトリを優先する。**

## 0. この依頼の目的と作業権限（最優先）

### 目的

従来の流体・接触・荷重射影などの検証時に増えたデバッグ用出力・計測コードを棚卸しし、**数値計算そのものを変えず**に明らかに不要なものだけ整理する。後続の研究では左右非対称・非周期・複雑振動を調べるため、その解析に有用な出力は早まって削除しない。

今回実施してよいのは以下の **二段階だけ**。

1. **Phase 1 — 棚卸し**：ソース、ヘッダー、ビルド設定、パラメータ、`tools/`、入出力、依存関係を調べ、機能の維持／削除候補を根拠付きで分類する。
2. **Phase 2 — 限定整理**：本書の「自動削除許可リスト」に載った**診断専用処理だけ**を、事前・事後の検証が通った場合に限り除去する。判断が分かれるものは **削除せずレポートで提案する**。

**Phase 3（ディレクトリ再構成・モジュール分割）は実施禁止。** Phase 1 の調査結果として再構成の候補を簡潔に書くことは可。ただし、ファイル移動、リネーム、CMake のターゲット再構成、`src/` と `include/` の分割や新サブディレクトリの作成はしない。

### 絶対に残すもの

- **VTU 出力機能**：`Simulation::writeVTKCombined(...)`、左右声帯の変形後節点座標、セルの connectivity / offsets / types とその出力仕様。VTU入力、モード読み込み、幾何構造を含む関連経路も残す。
- **正弦波加振の試験モード**：`iforce == 1`、`forcef`、`famp`、`forceDirection` と左右の加振方向・力の配分。通常の `iforce == 0`（流体加振）も維持。
- 通常の時間発展と連成計算：流路断面生成、声門面積、流量、圧力、圧力→表面力、接触・めり込み、接触反復・収束判定、モード力射影、Newmark 時間積分、モード変位→節点変位、WAV生成。
- 現行の有効な入力仕様・パラメータ互換性、左右独立のモードと材料設定、接触判定、安全チェック、NaN・発散等の**異常処理**。
- 研究上必要な基本時系列・変位・流量・圧力・声門面積と、後述する「判断保留」の解析用出力。

### 無条件の禁止事項

- **物理モデル・数値アルゴリズムの変更禁止。** 定数、式、単位系、符号、正規化、力の向き、面積閾値、圧力回復クランプ、分離点探索、流路補間、接触探索・ペナルティ・減衰、モード重畳、タイムステップと更新順序、積分係数、収束条件、OpenMP 並列範囲、演算順序を変更しない。
- **VTU出力の新規有効化／復旧を勝手に行わない。** 確認対象の `simulation.cpp` では関数本体は存在するがループ内呼出しがコメントアウトされている。今回はこれを「現状の制約」として報告するだけ。勝手な復旧、出力間隔変更、結果ディレクトリ変更、形式変更は不可。
- **パラメータフォーマットを変更しない。** `readParams.cpp` には古い `iforce` スロットと実効 `iforce` スロットが併存する。前者が `legacyIforce` と呼ばれていても、既存ファイル互換性のための読み取りなので今回は削除禁止。オプション値の解釈も変更禁止。
- モデル入力の VTU / NAS / 周波数データ、`input/` の既存ファイル、研究データ、過去出力、図表、`.gitignore` を削除／移動／上書きしない。テストランにより `output/` が上書きされ得るので事前退避策を立てること。
- `git clean`、`git reset --hard`、強制 checkout、`rm -rf`、履歴書換え、`git commit`、`git push`、ブランチ作成・切替、勝手な依存追加／インストールは禁止。
- `-ffast-math` の追加、浮動小数点演算の「最適化」、外見上の整形を口実とした式の移動、ループの並列化・統合をしない。
- `tools/` の解析スクリプトを「名前が古い」「未使用に見える」などの理由だけで削除しない。今回は**一覧と参照関係の調査のみ**。
- この文書を解釈して作業範囲を拡張しない。改善点・バグらしきものを発見しても修正せず、別途提案として報告する。
- あいまい・未検証な箇所について、確認なしに「安全だから削除可能」と判断しない。

7. テスト用一時ファイルはリポジトリ外（例：安全に確保できる `/tmp/...`）に置く。既存の本番 `input/param.txt` は編集しない。

## 2. Phase 1：必須棚卸し（まだコードを変更しない）

### 2.1 全機能・入出力の目録

実リポジトリ全体を調べる。対象は少なくとも以下。

- `src/*.cpp` とサブディレクトリ、`include/`、`CMakeLists.txt`、`input/` の設定、`tools/`、`tests/` があればそれも。
- 主要呼出しチェーン：`main` → `Simulation::initialize/run` → `ChannelSectionBuilder` / `FlowModel` / `ForceCalculator` / `ModalProjector` / `TimeIntegrator` / `State` → 出力。
- 実行モードの分岐（`iforce` 等）、接触有無、声道有無、VTU出力条件、`PROFILE_CALCDIS` などコンパイル時の分岐。
- 書き込む**全ファイル**と、書き込み元の関数・実行頻度・内容・単位・参照している解析スクリプト。`../output` への直接書き込みも含める。
- `tools/` の各スクリプトについて「読んでいるファイル」「解析目的」「現行出力と両立」「似たスクリプト」の対応表。**削除はしない**。
- その他のテスト・診断・legacy/current 比較が実リポジトリにあれば、存在場所、呼出し元、今も有効かを調べる。**存在を推測しない。**
- 使われていないローカル変数、ログ専用メンバー、未呼出し関数は `rg` だけでなく宣言・参照・間接的な依存まで確認する。特に計算結果に使う変数はログ用途と兼用され得る。

レポート用に以下の列をもつ表を作成する（実在するもののみ）。

`ID | パス:関数/変数/出力ファイル | 機能と呼出し条件 | 依存元/参照先 | 判定 | 理由（参照箇所） | 計算影響リスク | Phase 2 実施可否`

判定は次の **5種類のみ**：

- `KEEP_CORE`：通常計算、物理計算、安全判定、設定・互換処理。
- `KEEP_TEST`：正弦波加振、VTU、動作確認に必須のもの。
- `KEEP_OUTPUT`：基本出力または非周期・左右非対称振動の研究解析に使えるもの。
- `REMOVE_SAFE`：出力・計測にしか寄与せず、後述の自動削除許可リストに載り、依存関係検証済みのもの。
- `REVIEW_ONLY`：不要そうでも用途・依存関係が不確か／今後必要になり得るもの。**削除禁止**。

`REMOVE_SAFE` は名前やコメントで判断しないこと。読まれる先が無く、出力以外の副作用が無く、除去後も主な計算値・分岐・例外・メモリ初期化が不変であることを示す。

## 4. 実施手順：ステップごとのゲート

### Step A — 実行前の証拠保存

1. `git status` がクリーンであることを記録。
2. `input/param.txt` と、そこから実際に使うすべての VTU / NAS / 周波数 / パラメータ等の存在を検証。
3. 正規のビルド手順を `AGENTS.md` で確認（例：`cmake -S . -B build -DCMAKE_BUILD_TYPE=Release` → `cmake --build build -j`。Intel `icpx` および OpenMP 必須の可能性）。**ビルドできなければ変更に進まない**。
4. 計算前の既存 `output/`・`result/` を必ず保護し、上書き回避できる安全な場所／手段を用意。既存データへの影響がないと保証できないなら実行しない。
5. 基準実行の再現条件を記録：Git commit、コンパイラの種類とバージョン、ビルド設定、`OMP_NUM_THREADS` / `OMP_PROC_BIND` / `OMP_PLACES`、入力の SHA256、実行時作業ディレクトリとコマンド。
6. 正常な短時間の流体加振テスト（`iforce=0`）と、短時間の正弦波加振テスト（`iforce=1`）を用意。**既存の入力ファイルを変更せず**一時コピーを用いる。パラメータは正式なフォーマットを読み、`legacyIforce` と実効 `iforce` の位置に注意。小さい `nstep` を使う場合も元ファイルは保存する。
7. 実行できた場合のみ出力・終了コード・標準出力・警告・主要CSV/DAT/WAVを基準として保存する。出力を恒久的に増殖させない。正弦波試験では通常流体加振と同じ音声圧力波形を期待しない。

**重要**：提供コードではモード入力ファイルが `simulation.cpp` にハードコードされ、`build/` 基準の相対パスがある。テストの都合だけでこのパスを直さない。また、`AGENTS.md` にあるように実行カレントディレクトリが重要。復元不可能な変更を伴うテストをしない。

### Step B — Phase 1 レポート確定

変更前に `cleanup_inventory.md` をリポジトリルートへ生成してよい（新ディレクトリは作らない）。以下を必ず含める。

- ファイル・関数・出力の目録と上記判定、実際の参照箇所（相対パスと行番号）。
- **今回自動整理可能なもの**と**ユーザーの別途判断が必要なもの**の分離。
- `tools/` → 出力ファイル依存表。
- 動作モード（`iforce=0/1`、接触有無、声道有無、VTU出力状態）の表。
- 削除候補ごとの依存判定、既存コードの変更が必要な箇所、削除リスク。

### Step D — 数値・入出力の回帰テスト（必須）

- 比較対象は baseline と変更後で **同じ入力、同じコンパイラ／フラグ／作業ディレクトリ／OpenMP設定**を使うこと。

- 数値変更を意図していないので**まずバイト一致を期待する**。書式差が生じた場合は自動的に合格にせず理由を調べる。数値列を比較する場合の暫定的な上限は `abs_tol=1e-12`, `rel_tol=1e-10`（ファイルに記載された単位で比較）とし、**少しでも理由不明の差があれば不合格**。NaN、Inf、行数、時刻／step、出力頻度、欠損列の違いは不合格。

- VTUが baseline で実際に生成されていた場合、ファイル数、時刻に相当する番号、頂点数・セル数、接続情報、左右両側の `Points` を比較する。**現状コメントアウトにより生成されない場合は「生成されず・関数保持の静的確認のみ」と書く**。出力復旧を捏造したり勝手に有効化しない。
- 削除した診断ファイルが生成されないことを確認。削除対象でないファイルの欠落は禁止。
- 実行途中の発散、クラッシュ、テスト不足、コンパイル警告の新規発生、重要出力の変化があれば **不合格→今回変更を撤回する**。本書の範囲外のバグ修正でごまかさない。

## 6. 重要な注意点：見た目はデバッグでも削除禁止となり得る

- `simulation.cpp` の `writeVTKCombined` は呼出しがコメントアウトされていても **必要機能**。コメントアウトされたコードを機械的に一括削除しない。
- `rungeStep.cpp` に RK 系関数が残っていても「Newmarkを使っているから不要」とは判断しない。呼出し関係を報告するだけ。
- `forceCalculator.cpp` の `maxPenetration`、各種残差、接触反復終了フラグは数値計算の分岐に関わる。診断の削除に伴って消すと結果が変わる。
- `contactForceL_ij` / `contactForceR_ij` は監視出力から参照されても、接触力分配ラムダに渡される。今回は削除しない。
- 変形後の流路断面、`psurf` の圧力回復、分離点 (`sepIndex`)、`flowBlendLengthMm`、`flowSeparationAreaRatio`、`kAreaClosed*`、`g3` の各処理は検証で重要だった物理計算そのもの。**不要な診断値を減らすこととモデルを単純化することは別**。
- `Geometry::surfExtractFromNAS` は自動格子検出およびVTU節点対応の根幹であり、以前の固定寸法らしい引数を見つけても削除・変更しない。
- 異常時の検出・例外・エラー表示と、ただ大量にCSVを吐く詳細診断とは区別する。安全確認処理の removal は許可しない。
- `AGENTS.md` に「出力に影響しない高速化方針」等の文書が挙がっていても、本作業は高速化ではない。不要出力の削除による実行時間変化は計測してよいが、速度改善のための計算改造は禁止。
