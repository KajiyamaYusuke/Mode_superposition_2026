# 261103 body-ratio flow study

The solver inputs are prepared from the completed L12_R6_P900 reference, with 36 independent 1 s parameters, T3 d2 surface and deformation VTU output disabled. `prepare_sweep.py` creates new case directories and refuses to overwrite existing ones. `run_sweep.py` audits inputs and solver hashes, isolates output, and preserves status and logs. It will not silently replace an existing case. `--remaining --resume` requires both representative runs to have completed and validates existing completed outputs before skipping them.

`continue_after_representatives.py` is the sequential coordinator: it waits for the existing representative process, verifies both completed cases, writes representative QC, then starts the remaining cases and finally analyzes saved data. Failures stop the chain. Check the study's `continuation.log`, per-case `status.json`, and logs before any restart. The separate representative process and coordinator are both necessary while the representative cases are in progress; a stale `RUNNING` status after interruption does not mean a process is alive. Failed or incomplete directories are intentionally preserved.

`analyze_flow_jitter.py` contains Ug metrics and independent event/periodicity checks. `template_period.py` explores ACF plus template matching, including explicit ambiguity when ACF and spectral periods differ. It does not force alternating intervals into a single period. `analyze_saved.py` reads completed waveforms, separates solver and Jitter status, and writes candidate event and cycle tables. Candidate values in diagnostic CSVs are not automatically valid Jitter; check the status. `plot_jitter_sweep.py` leaves missing results blank and labels candidate-only comparisons. The tracker remains conservative; high-quality flow data can be valid even when Jitter is undefined.

Tests: `python3 -m unittest tools.tests.test_body_ratio_inventory tools.tests.test_body_ratio_jitter tools.tests.test_template_period tools.tests.test_analyze_saved_flow tools.tests.test_body_ratio_run_sweep`.

For the user-requested 900 Pa-only continuation, run `python3 tools/body_ratio_jitter_261103/run_sweep.py --execute --pressure-900 --resume --threads 4`. This checks the completed 900 Pa representative and does not require or run the failed 1400 Pa representative. View current case states with `python3 tools/body_ratio_jitter_261103/status_900.py`. After all 18 cases pass, `finish_900.py` validates saved outputs, runs analysis and creates `analysis_900_complete/`. The analysis watchdog and simulation runner are distinct processes; an interruption may leave `RUNNING` metadata, which is not proof that a process is still alive. Never start a second runner concurrently or overwrite an incomplete case directory.
